# Web2 → Web3 交易所后端工程师 · 20 周全职课程包

> 目标读者：学员本人。这是你 20 周的总地图：学什么、为什么、怎么学、怎么验收、期望与现实。
> 课程的技术地基（阶段表/周次/弹性档/每日节奏/术语）以 `roadmap.md` 为冻结基线，本文件与其一致。

## 一、这张课程包是什么

面向 **Web2 前端/全栈 → Web3 交易所 Go 后端** 转岗的完整课程包，交付物包括：

- **周计划与阶段讲义**（lecture.md / tasks.md / checklist.md / resources.md 四件套 × 8 个阶段）
- **项目规格书与验收标准**（SPEC × 5 + 完整项目 10 条验收标准）
- **代码脚手架**（Go 服务骨架、docker-compose、CI 流水线、WS 网关、k6/pprof、Foundry 工程）
- **面试冲刺题库**（系统设计 8 题、Go 深挖 60 题、算法 180 题、英文工具包、Mock 流程）

主线是 **CEX 后端**（Go 覆盖交易所后端工作量 70%+），辅线是**链上**（以太坊学到项目级深度，Solana 学到够用线）。

## 二、学员画像（写给你的）

- JS/TS 熟练、会 React，已经有「用代码造东西」的肌肉记忆——这是资产，不是负债。
- **无后端工程经验**：没写过服务端、没碰过数据库/消息队列/部署。这是本课程的填充目标。
- 每天全职学习 **4-8 小时**。
- 目标：入职大型 Web3 交易所（币安/欧易/Bybit/Bitget/Gate 等）做 Go 后端/开发。

对你的三个基本盘判断（来自岗位调研原文）：

1. **Go 是交易所后端的主流与硬要求**——入职第一年你写的 70%+ 代码都是 Go。
2. **区块链知识在 JD 中是 nice-to-have**——但你比纯 Web2 候选人多一段「能讲链上入账/reorg/签名」的故事。
3. **面试权重**：算法 20-30% / 系统设计 30-40% / 八股 15-25% / 项目深挖 10-20%；OKX/Bybit 要求中英双语。
   课程时间分配按这个权重重建，见 `roadmap.md` 第 8 节。

## 三、目标岗位与现实定位

**课程结业时你所在的位置（诚实版）**：

- ✅ 可直接投：中国背景中小交易所 Go 后端 1-3 年档（Bitget/Gate/HTX/MEXC/KuCoin 类）、中小钱包/做市/行情数据公司、Web2 Go 初级岗（保底）。
- ✅ 路径：中小所积累 1-2 年 → 内推跳头部。
- ⏳ 还需 1-3 年再投：头部所本部（币安/OKX/Bybit 本部 3-5 年经验档）、撮合/低延迟专项、合约全职岗。

**不承诺入职**。最大风险是简历关（学历/年限在 HR 筛选被拦），对策是内推优先 + 项目集当简历附件 + 投递 100+ 岗位管理；英语 20 周只能保住「能讲」；系统设计深度与 5 年从业者有差距，面试以「我做过的取舍」诚实表述为加分项。

## 四、课程总览：20 周，三档弹性

### 6.2 四件套怎么用（00-startup/ 及以后每阶段目录）

| 文件 | 是什么 | 怎么用 | 什么时候用 |
|---|---|---|---|
| `lecture.md` | 本阶段讲义：概念讲解、关键接口签名、参考实现要点、测试期望、常见坑 | 主课精读；先看「交易所场景对应」，再读原理；读懂的立刻做最小 demo | 每天主课时间 |
| `tasks.md` | 任务清单：每个任务有预计时长/前置/输出物 | 按序执行；先做前置为空的；做完勾掉 | 每天项目时间 + 主课练习 |
| `checklist.md` | 本阶段验收勾选：全部布尔可判 | 每条只有是/否；答案全为「是」= 阶段完成 | 每周六 + 阶段末 |
| `resources.md` | 资源：标「必读」与「选读」 | 必读=主线，选读=学有余力（弹性档直接跳过） | 主课配套 / 晚间选做 |

### 6.3 如何按周推进

1. **周一**：读本周 `lecture.md` 开头 + 通读 `tasks.md`，把周任务摊到 6 天，锁定本周里程碑。
2. **周二至周五**：按 `daily-rhythm.md` 的当日作息执行；每日结束前写三行日志并 commit。
3. **周六**：跑 `checklist.md` 本阶段勾选；缺证据的条补证据（截图/命令输出/录屏）。
4. **周日**：复盘一周（踩坑与取舍写进 ADR 或 `docs/review.md`）+ 规划下周；下午休息。
5. **项目周结束时**：按「10 条验收标准」全量验收，见 6.4。

### 6.4 项目怎么验收

每个完整项目（P0-P4）统一执行 `standards/project-acceptance-10.md` 的 10 条：

1. 测试完备（覆盖率 ≥ 80% + fuzz/边界用例）
2. 真实部署（testnet + 源码验证）
3. 安全自查（Slither/威胁模型）
4. 文档齐备（架构图 Mermaid + ADR）
5. 可演示（3-10 分钟录屏）
6. 完整闭环（UI/CLI 走通全业务流）
7. 可复现（依赖锁死一键重跑）
8. CI 自动化
9. 复盘文档（踩坑 + 取舍）
10. 结果留痕（报告/地址/CI 绿标截图）

验收流程：每项目结束 → 对照 10 条自测 → 补齐证据 → 录屏 → 结论记录到 `QA/review-log.md` → 结果写进该项目的 README 和你的简历。任一条件为「否」= 项目未通过，修复后再验。

### 6.5 三档怎么选

- 每天能稳定 6h+ → 标准档（默认走完 20 周）。
- 脱产且想压缩总时长 → 冲刺档，先提速不砍内容，仍超期再按砍项指南砍。
- 每天只有 4h → 最低档，接受 22 周 + 按清单砍项（别硬撑全量，砍项比烂尾好）。
- 判断是否要调档：连续两周完不成当日任务 → 下调一档并执行对应砍项；连续两周提前完成 → 上调。

## 七、免责边界

- **不承诺入职**。课程把你在 20 周内送到「可投递状态」，入职取决于简历关、面试表现与市场行情。
- 英语是长期的：20 周只保「能讲」（自我介绍 + 项目讲述 + 术语库 100 词），不等于流利。
- 系统设计深度与 5 年从业者有差距：面试中「我做过的取舍」是诚实且加分的表述，不要背大词。
- 学习效果取决于每日投入与「跑通优先」执行度；卡壳不换路、笔记只摘抄，是进度最大的敌人。
