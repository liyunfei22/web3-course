## 2. 一条命令起三个中间件（MySQL 8 / Redis 7 / Kafka 3.x KRaft）

**直觉**：你以后写的每个 Go 服务都要连 MySQL（主存储）、Redis（缓存/分布式锁）、Kafka（事件流）。不装原生应用，而是用 Docker 容器管理：镜像即环境，删库重来一条命令。

**要点**：
- **KRaft 模式**：Kafka 3.x 起 Kafka 自己管理元数据（不再依赖 ZooKeeper），单容器即可跑起来；这是本课程的技术栈决策（roadmap 第 2 节）。
- **healthcheck**：compose 里每个服务配健康检查，`docker compose ps` 全部 healthy 才算连通成功——checklist 的判据就长这样。
- **验证三连**：`SELECT 1`（MySQL）/ `PING`→PONG（Redis）/ 列 topic（Kafka），三步全过才继续。

**常见坑速查**：镜像拉不动（换镜像加速或代理）；端口被占（`lsof -i :3306` 查，换宿主端口映射）；容器起来了但 MySQL 认证失败（mysql8 默认 `caching_sha2_password`，客户端/驱动版本要新）。

compose 文件与验证命令在 `tasks.md` D2 给出（Phase 0 最小版，内嵌开发密码；正式版已由 A2 交付于 `../scaffolds/docker-compose.md`——mysql:8.0 + redis:7.4-alpine + Kafka KRaft，密码/库名走 .env，P0-M1 起切换使用正式版）。

**课程协议**（读完即视为签署，把你的承诺写在动机页末尾）：
1. **每日 commit**：每天至少 1 个 commit push 到组织仓库（含当天日志/笔记/代码产物）。
2. **每日三行日志**：`00-startup/journal/YYYY-MM-DD.md`，三行硬结构：完成（可验证产出）／卡点（至少 1 条，超 30 分钟写「现象→根因→解法」）／明日起点。模板见 `../daily-rhythm.md` 第 5 节。
3. **跑通优先**（run-first）：先打通最小全链路，再补正确性与优化；判断标准只有「链路通了吗」。
4. **卡壳 30 分钟规则**：单个点 30 分钟无进展即换路（官方文档 → 换实现路径 → 简化 → 记录后跳过）。

## 6. 前端 → 后端认知盲区自评 10 题

**规则**：不许查资料，每题 60 秒口答。答不出的点记下来——它们就是 Phase 1 重点投入的章节（本课程存在的意义）。完成标准：盲区 ≤ 3 个 = 启动合格；> 3 个 = Phase 1 的「主课 II」时间多投给 W1-W2。

1. 浏览器输入 URL 回车到页面首帧，网络层面依次发生了什么？每一步谁在等待？
2. 服务器「同时」服务 1000 个用户：进程 / 线程 / 协程 / I/O 多路复用，分别是怎么做到的？
3. 「事务」解决什么问题？A 有 1000 元向 B 转 100 元，转账中途崩溃会发生什么？
4. 数据库索引为什么能加速查询？为什么不能给所有列都建索引？
5. 订单系统部署了多个实例，用单机互斥锁能防止重复扣款吗？为什么？
6. 为什么需要「消息队列」？直接 HTTP 调用下游服务有什么不行？
7. 「幂等」是什么意思？举一个「同样的请求发两遍会出事」的业务场景。
8. 哪些数据适合进缓存？缓存与数据库数据不一致怎么办？
9. 服务崩溃重启后，哪些数据会丢？「先写日志再改数据」为什么能救回来？（直觉即可）
10. 你现在最陌生的 Web2 后端概念是哪一个？用 100 字写「我目前理解的它」，并标注不确定的部分。

## 7. 参考答案（要点，先自评再对照）

1. **DNS 解析 → TCP 三次握手 → TLS 握手（HTTPS）→ HTTP 请求 → 服务器路由 → 中间件链 → 业务逻辑 → 数据库 → 响应 → 浏览器渲染**。盲区判据：说不出「中间件」和「数据库在链路里的位置」= Phase 1 W1 主课重点。
2. 主流是**线程池 + I/O 多路复用（epoll）**；Go 用 **goroutine（协程）+ GMP 调度器**。盲区判据：说不清「阻塞 I/O vs 非阻塞 I/O」= W2 重点。
3. 事务 = 一组操作要么全成功要么全不生效（**ACID**）。崩溃会导致 100 元消失或双份；回滚（原子性）防止。盲区判据：说不出 ACID 四字母含义 = W3 重点。
4. **B+ 树索引**把全表扫描变成树搜索（对数级）；每个索引是一份额外副本且拖慢写入。盲区判据：说不出 B+ 树 = W3 重点。
5. **不能**：内存锁只对单进程内的线程有效；多实例需要跨进程互斥 = 分布式锁（Redis `SETNX` 等）。盲区判据：没意识到「锁的作用域」= W4 重点。
6. 消息队列三价值：**解耦**（下游挂了不阻塞上游）、**削峰**（洪峰进队列排队）、**异步**（用户不等慢下游）。HTTP 直连：耦合、无缓冲、重试机制缺失。盲区判据：说不全三点 = Phase 2 主课重点（本阶段先要直觉）。
7. 幂等 = 同一操作重复执行、结果一致。例：支付/充值回调重复投递；扣款请求重发。正解：**幂等键 + 唯一约束**。盲区判据：说不出解法 = W3（唯一约束）与 Phase 2（Outbox）重点。
8. 读多写少、变化不频繁、允许短暂不一致的数据。一致性靠**失效策略**（旁路缓存：先写库、后删缓存）与 TTL 控制。盲区判据：说不出失效策略 = W4 重点。
9. 内存数据丢，磁盘数据不丢；「先写 WAL（预写日志）再改数据」保证崩溃后重放恢复——MySQL 与撮合引擎（P2）同思路。第一次听说 WAL = 正常，届时细讲。
10. 自评题。写完后把这段文字贴进 `journal/startup.md`，20 周后回看。
