# applying.md — 投递策略：公司分层、内推渠道、投递表与 JD 自查

> 定位：roadmap W20「简历 2 页 + 投递表」的配套作战手册；与 `resume/resume-template.md`（简历）、`mock-interview.md`（面后复盘）配套使用。
> 时间线建议：W18 简历定稿 → W19 完成第一轮投递（前 3 家热身练手）→ W20 全量投递（Mock3 达标后再投重点目标）。投递开始后每天花 20-30 分钟维护投递表，「投了就忘」等于浪费机会。

## 一、目标公司分层表（按岗位目标排序）

| 梯队 | 公司与岗位 | 匹配点（你的弹药） | 投递节奏 |
|---|---|---|---|
| 第一梯队：交易所 Go 后端/开发 | **Bitget / Gate / HTX / MEXC / KuCoin** 的 Go 后端、Go 开发、交易系统开发、钱包后端岗位 | P2 旗舰（撮合/账务/行情 WS/充提）+ P1 链上监控，正好覆盖 JD 的「撮合/订单系统/钱包/资管」关键词；公司规模与岗位要求适合 5 个月转型者 | 首批 3-4 家，每家投 2-3 个相关 JD（同一家一周内投完），用「热身 3 家」的心态练面试 |
| 第二梯队：周边基础设施 | 钱包（Cobo/OneKey 等、托管类）、做市商/量化团队（后端类）、行情数据/索引服务商、交易所生态工具公司 | Go + 链上索引 + WebSocket 推送（P1/P2）直接对口；竞争比头部交易所略小，是「曲线进交易所生态」的入口 | 与第一梯队平行投；重点找「Go 后端」字样的岗 |
| 保底：Web2 Go 后端 | 各中型互联网公司 / SaaS / 支付类 Go 岗位 | P0 + P2 的 Go/MySQL/Redis/Kafka 全套能力已达标；作为收入与经验保底，同时继续冲第一梯队 | 每周 2-3 家；谈「1-2 年后回 Web3」也给 PoR/P2 加分 |
| 长期：币安 / OKX / Bybit | 头部交易所（通常要求 3+ 年 Go 或名校/大厂背景，JD 硬门槛高） | 现状直接投大概率被筛掉；策略 = 先在第一梯队或 Web2 积累 1-2 年后带「实盘经验」再投（roadmap 面试权重调研的结论与之一致） | 阶段 1：不投正式岗，仍可关注校招/专项/Web3 社区内推位；阶段 2（1-2 年后）：带着第一梯队经验投 |

**写明原则**：第一梯队 = 主战场（岗位画像最贴合）；第二梯队 = 平行加分；保底 = 抗风险；长期 = 有明确路径，不在 W18-20 浪费投递次数。

## 二、内推渠道（按优先级）

| 渠道 | 怎么做 | 要点 |
|---|---|---|
| 前同事 / 熟人（最重要） | 微信/脉脉直接发：简历 + 一段 3 行自我介绍（含项目数字）+ 目标岗位链接 | 消息别群发模板，改成每人都提一句共同经历；被拒也要感谢并记入投递表 |
| 脉脉 | 搜公司名 + 「Go 后端」，看在职员工；<100 字私信：我是转岗 Go 后端、做过撮合引擎，求内推或指点 | 别只发「求内推」三个字；可以连续礼貌跟进 1 次 |
| 牛客（校招/实习居多，社招也用） | 查目标公司面经与内推帖；内推帖里通常有官方内推码 | 面经存进 `interview/mock/` 面经库，投递前先看该公司最近 3 个月面经 |
| 一亩三分地 / Reddit r/cscareerquestions 等中文社区 | 海外/外企岗位情报；讨论帖里常有「我们组在缺人」的信号 | 主要提供情报，内推转化率低，别花太多时间 |
| Web3 社群 | 各交易所/钱包的开发者社群（Discord/Telegram/微信群）；群公告常挂招聘 | 在群里输出价值（回答问题/写开源 PR）后再提求职，转化率更高；课程期间已积累的「产出型笔记」就是展示物 |
| 招聘平台直投 | Boss 直聘/猎聘搜「Go + 交易所/钱包/撮合」；看到 JD 直接投（无内推时直投不亏） | 用一条「打招呼语」模板：一句话转岗背景 + 一句话项目亮点 + 一句求面试 |

**铁律**：拿到内推 = 3 天内投出；被内推人催材料 = 简历与投递表已就绪（这就是为什么先做简历再谈内推）。

## 四、JD 关键词匹配自查表（投递前逐岗对照）

对每个目标 JD 复制一份下表，逐词勾选「JD 出现 → 我的证据在简历第几行/哪个项目」，凑不齐 6/8 的岗位要么降期望投，要么先补证据再投。

| JD 关键词 | JD 里常见写法 | 我的证据链（简历行/项目/数字） | 达标 |
|---|---|---|---|
| Go | 「熟悉 Go/GMP/并发模型」「golang」 | P2/P1 全程 Go；goroutine/channel/context 用在 WS 网关与扫块并发 | ☐ |
| GMP / 并发 | 「理解 goroutine 调度」「并发正确性」 | `list-concurrency.md` 15 题过完 + P2 按 symbol 分片单线程的设计论证 | ☐ |
| Redis | 「Redis 缓存/分布式锁/队列」 | P0 短链缓存 + P2 订单簿快照/行情状态 | ☐ |
| Kafka | 「Kafka 消费组/顺序/幂等」 | P1/P2 事件流 + Outbox + 幂等消费（重平衡坑写在复盘） | ☐ |
| MySQL | 「数据库设计/事务/主从」 | P0 表设计 + P1 充值幂等唯一索引 + P2 账务事务 | ☐ |
| 幂等 | 「幂等/去重/防重」 | P1 (txHash, logIndex) 唯一键 + 重复投递验证 200 次恰好 1 次的记录 | ☐ |
| 撮合/订单 | 「撮合引擎/订单系统/盘口」 | P2 M1 内存订单簿、价格-时间优先、WAL+快照 | ☐ |
| 钱包/链上 | 「钱包/充值/提现/链上监控」 | P1 扫块确认数/reorg 冲正 + P2 M4 冷热钱包/签名/归集 + P3 Solidity 部署 | ☐ |

**使用规则**：8 词中 ≥6 词能当场说出证据 = 可以投；否则先补（补法：回项目加 README 记录或做一道相关题，而不是硬投）。填完的表格存 `interview/applying-JD-sheet.md`，是面经库与复盘的一部分。

## 五、投递节奏与跟进纪律

1. **每周节奏**：第一/二梯队合计 ≥ 3 家新投 + 2 次跟进；保底梯队 1-2 家。
2. **跟进模板**（投后 5-7 天，渠道按内推/HR）：「您好，我是 X（内推人 张工 推荐的候选），X 号投递了 Go 后端岗。这是我的 GitHub（仓库与压测报告），方便了解进展吗？也欢迎约时间进一步沟通。」
3. **被拒处理**：24 小时内复盘（面经卡 + 改进点），目标公司可 6 个月后再投（换 JD 或等新岗位）。
4. **offer 取舍**：拿到保底 offer 不阻断后续面试（可以谈入职时间）；第一梯队 offer 到手 = 主任务完成，向长期目标（币安/OKX/Bybit）的「1-2 年计划」开始执行。
5. **进度指标**：投递数、面试数、通过率、offer 数四类数字每周末记一次——数字不涨 = 渠道或简历有问题，回滚检查。
