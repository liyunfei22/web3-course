# mock-interview.md — 模拟面试流程脚本（四轮评分卡制）

> 定位：Phase 7（W20）核心交付「2-3 场完整 Mock」的操作手册（roadmap 第 3 节 Phase 7 / 第 8 节：Mock = 四轮评分卡制）。
> 前置：W18 系统设计 8 题已各练 1 遍、W19 算法 180 题已刷 80%+、go-deep 60 题过完、简历定稿（`resume/resume-template.md`）、英文讲述稿三版（`english/project-scripts.md`）录过音。
> 使用方式：本文件给「面试官」与「被面试者」两份脚本。每场 Mock 必须录音/录屏，结束后 30 分钟内完成计分与复盘表。全部材料可提交、可复述、可被真正面试官查看（产出型笔记）。
> 原则：Mock 的目的是「暴露问题」，不是「证明自己」——诚实记录每一次卡壳，并写进复盘计划。

---

## 0. 总流程与节奏（一次 Mock = 一个上午/下午）

| 步骤 | 时长 | 说明 |
|---|---|---|
| 准备 | 10 min | 面试官拿到本场题目包（本文件各轮题库随机抽）；被面试者就位，准备好白板/画图工具；打开录音 |
| 算法轮 | 45-60 min | 2 题（1 热身高频 + 1 Medium 偏难），含并发题备选 |
| 休息 | 5 min | |
| 系统设计轮 | 60 min | 1 道设计题（从系统设计 8 题清单抽），口述 + 画图 |
| 项目深挖轮 | 45-60 min | 深挖 P2 旗舰项目（10 题中抽 3-4 题）+ 1 个 P1/P3 交叉问题 |
| 行为轮 | 45 min | STAR 追问 3-4 题 |
| 复盘 | 30 min | 双方按评分卡逐项打分 + 指出 3 个最需要改的点 + 录入复盘表 |

目标：每场 Mock 产出 3 件东西——①四轮评分卡（1-5 分逐维）②「改进点清单」（最多 5 条，按优先级）③录音回听笔记（1 页）。20 周内共完成 3 场：Mock1 约 W18 末、Mock2 约 W19 末、Mock3 在投递开始前（W20 初）。

## 1. 算法轮（45-60 min）

### 1.1 流程与时间分配

| 段落 | 时长 | 动作 |
|---|---|---|
| 开场 + 自我介绍 | 2-3 min | 面试官让被面试者用 30 秒介绍自己（练 1 分钟自我介绍的前半段） |
| 第 1 题（热身高频） | 15-18 min | 推荐类目：数组/双指针、链表、二叉树层序 |
| 第 2 题（Medium 偏难） | 20-25 min | 推荐类目：滑动窗口、单调栈、DP、或并发题（见 `algorithms/list-concurrency.md`） |
| 反问收尾 | 2-3 min | 面试官：你还有什么问题（候选人也练这个） |

### 1.2 评分维度（每题，1-5 分）

| 维度 | 5 分标准 | 1 分标准 |
|---|---|---|
| 理解题意 | 先主动问清输入/输出/边界/复杂度期望，再动笔 | 上来就写，跑偏方向 |
| 思路沟通 | 先说思路 + 复杂度再写码，边写边讲 | 闷头写不解释 |
| 正确性 | 写完立刻自测用例（含边界：空/单元素/溢出），命名清晰 | 没有自测，样例都不过 |
| 复杂度 | 主动给出时间/空间复杂度，必要时说出优化方向 | 说不出复杂度 |
| 代码质量 | 无冗余、变量名准确、无死代码 | 逻辑混乱、反复涂改 |

**示例题目集（3-5 题/轮，从 `algorithms/list-core.md` 对应类自选）**：
- 两数之和 → 追问「如果输入有序呢？如果所有组合都要呢？」（期望：哈希 → 双指针 → 去重）
- LRU 缓存 → 追问「get/set 都是 O(1) 怎么保证？用什么数据结构组合？」
- 二叉树层序遍历 → 追问「锯齿形呢？右视图呢？」
- 无重复字符的最长子串 → 追问「如果字符集巨大/允许 k 次替换呢？」
- 合并 K 个升序链表 → 追问「改用优先队列复杂度多少？」
- 接雨水 → 追问「单调栈 vs 双指针？」
- 交替打印（并发题）：从 `list-concurrency.md` 抽 1 题，追问「race 条件在哪？-race 怎么验？」

### 1.3 常见追问集（面试官在每题结束后依次问）

1. 「这个方案最坏情况是什么？」
2. 「如果数据规模 ×100 呢？你的方案还成立吗？」
3. 「能原地完成吗？额外空间是多少？」
4. 「手写几个边界用例走一遍你的代码（面试官指定：空输入/全相同/最大数）。」
5. 「你上一版本说 O(n)，现在这段代码真的是 O(n) 吗？哪里会让它退化？」

## 2. 系统设计轮（60 min）

### 2.1 流程与时间分配（经典 4 段式）

| 段落 | 时长 | 动作 |
|---|---|---|
| 澄清需求 | 5-8 min | 面试官出题后被面试者先问：规模（QPS/TPS）、延迟目标、一致性要求、资金安全红线、客户端形态。不问清就设计 = 直接扣分 |
| 高层架构 | 15 min | 画图：客户端 → 网关 → 服务 → 存储/消息队列 → 外部依赖；讲清每个组件职责与数据流方向 |
| 深挖 2-3 个关键点 | 20-25 min | 面试官挑组件深挖（撮合如何保序？充值怎么幂等？WS 断线怎么恢复？） |
| 收尾评估 | 8-10 min | 被面试者总结 3 个取舍与 1 个可优化点；面试官按题给反馈 |

### 2.2 题目池（对应 roadmap W18 系统设计 8 题，逐题与旗舰项目 P2 对照）

| 题 | 一句话题干 | 与本课程项目对照 |
|---|---|---|
| ① 撮合引擎 | 设计一个支持 10 万 TPS 的撮合引擎 | P2 M1 内存订单簿（按 symbol 分片单线程、价格-时间优先、WAL+快照） |
| ② 充值确认与安全 | 充值入账如何做到不丢不重、防止 reorg 与伪造 | P1 扫块 + 幂等键 (txHash, logIndex) + 状态机 + 冲正 |
| ③ 订单流/Kafka 拓扑/WS 网关 | 下单到成交到行情推送的完整事件流 | P2 M2 Outbox + M3 行情 WS（快照+增量+seq） |
| ④ 三栏账务/事件溯源/精度 | 账户三栏模型与金额精度设计 | P2 M2 复式记账（frozen/available/total 恒等式） |
| ⑤ 三方对账 | 账本/链上/银行三表对齐方案 | P2 M4 对账服务（幂等可重跑） |
| ⑥ 冷热钱包 | 大额资产安全保管与出账流程 | P2 M4 冷热分层 + 归集 + 提现签名 |
| ⑦ 低延迟优化 | 撮合/行情链路低延迟的技术手段 | LMAX 架构 + pprof 调优对比（M5 产出数据） |
| ⑧ 高可用主备 | 单点故障时的切换与一致性 | P2 部署架构 + 主备讨论（写文档不实现） |

### 2.3 评分维度（1-5 分）

| 维度 | 5 分标准 |
|---|---|
| 需求澄清 | 先问规模/一致性/资金红线，后才动笔 |
| 架构完整性 | 组件齐全、数据流闭环、单点与故障有考虑 |
| 关键点深度 | 至少 2 个关键点（撮合保序/幂等/WS 恢复）能深入到伪代码级 |
| 残留风险 | 主动说 2-3 个取舍与代价（trade-off），不空谈完美方案 |
| 沟通画图 | 图清晰、术语准确（撮合引擎/matching engine、账务/ledger、行情 WS、白板 whiteboard） |

### 2.4 常见追问集

1. 「这个组件挂了怎么办？数据会丢吗？」
2. 「撮合结果怎么保证可重放到同一结果？」
3. 「QPS 翻十倍，哪个组件先死？怎么扩？」
4. 「WS 连接断了，客户端如何恢复到最新行情？」
5. 「精度怎么处理？1.000000000000000001 这种数在哪一层处理？」
6. 「异常订单（资金不足/重复下单）走哪条路径？」
7. 「你的方案里哪一步最可能出错？为什么？」

## 3. 项目深挖轮（45-60 min）

### 3.1 流程

| 段落 | 时长 | 动作 |
|---|---|---|
| 项目自述 | 5 min | 用英文讲述稿（`english/project-scripts.md`）的「30 秒版」讲旗舰项目 P2（不需要 30 分钟版，那留给真实终面） |
| 深挖攻击 | 25-35 min | 面试官从追问集中抽 3-4 题连续追问，每个回答要落到「具体数字/文件路径/commit」 |
| 交叉检验 | 10 min | 追问 1 个 P1 或 P3 的问题（证明项目是自己做的，且理解通盘） |
| 收尾 | 5 min | 面试官问「如果重做，你会改哪个设计？」 |

### 3.2 深挖题目池（P2 旗舰，10 题 + 追问）

1. 「你的内存订单簿怎么保证重启不丢单？」（期望 WAL + 快照回放；追问 checkpoint 频率）
2. 「frozen/available/total 三个数由谁维护、怎么保证恒等式？」（期望账务服务单一写者 + 事务）
3. 「同价订单怎么保证时间优先？用什么数据结构？」（期望 max/min-heap + 插入序）
4. 「k6 压测你是怎么做的？汇报具体数字并解释瓶颈。」（期望：并发数/QPS/P50/P99/错误率，pprof 前后对比）
5. 「充值入账的幂等键是什么？为什么必须有 logIndex？」（期望 (txHash, logIndex)，为什么——同 tx 内多个 Transfer）
6. 「reorg 时冲正的完整流程？你会不会把已提走的用户余额搞成负数？」
7. 「行情 WS 断线重连的快照恢复细节——seq 存在哪？」
8. 「提现签名私钥在哪？如果热钱包被黑怎么办？」
9. 「你项目里 Outbox 解决什么问题？如果业务事务失败但事件已发呢？」
10. 「说一个你中途改掉的方案，为什么改？」（评「取舍复盘」能力，对应验收⑨）

### 3.3 交叉检验题池（P1 / P3 各 5 题）

P1：①扫块用轮询还是 WS？为什么双轨？②pending/confirmed/finalized 三态判据各是什么？③确认数阈值你怎么定的？④某用户充值 100 USDC 但链上 status=0，你入账吗？为什么？⑤Kafka 消费者重启后为什么会重复读消息？你怎么保证不重复入账？
P3：①x·y=k 的 swap 公式推导一遍？②为什么用 sqrt 而不是直接比较乘积？③你的合约怎么防重入？④Foundry invariant 测了哪条不变量？⑤Slither 报了哪些？逐条你怎么处置的？

### 3.4 评分维度（1-5 分）

| 维度 | 5 分标准 |
|---|---|
| 事实细节 | 数字/路径/commit 都能说清，不靠记忆模糊 |
| 因果深度 | 每个决定能说「为什么这个方案、代价是什么、如果不这样会怎样」 |
| 踩坑真诚 | 主动讲失败（坑/回滚/压测翻车），有根因有修复 |
| 与八股连通 | 能把项目细节接到区块链八股（确认数/reorg/幂等/Outbox、CEI 等） |
| 英文可讲 | 关键 5 句能切换英文表述（晋级题） |

## 4. 行为轮（45 min）

### 4.1 流程与题目池（STAR 结构：情境-任务-行动-结果）

| # | 行为题 | 期望覆盖的要点 |
|---|---|---|
| 1 | 讲一个你独立从零做成的事（学习/项目皆可） | 5 个月转岗、P2 从 0 到验收 |
| 2 | 讲一个你出错/失败的案例，你怎么处理的？ | 压测翻车/消费重复/kafka 积压，按⑨复盘库取材 |
| 3 | 你怎么在时间紧张时排优先级？（同时多项目） | 弹性档砍项决策、每日 4-8h 计划纪律 |
| 4 | 你在团队/社区里帮助过别人或接受帮助的经历 | 开源/社群/内推、卡壳 30 分钟规则 |
| 5 | 你未来 1-2 年的职业规划？为什么从 Web2 前端转 Web3 后端 | 稳定叙事：技术主线 Go + 链上理解 |

### 4.2 追问集（目的：挤水分，检验真实经历）

1. 「具体数字是多少？（估计值要说明是估算）」
2. 「这件事里你个人做了什么 vs 别人做了什么？」
3. 「如果再来一次，你会第一步就做什么？」
4. 「这个坑的根因你最后挖到哪一层？」
5. 「当时的时间线是什么？（周几开始、几天解决）」——答不清 = 经历可疑或没复盘

### 4.3 评分维度（1-5 分）

| 维度 | 5 分标准 |
|---|---|
| STAR 完整 | 四要素齐全，无「感觉/大概」 |
| 真实可验 | 细节具体，时间线、数字、人名（可匿名）可交叉验证 |
| 反思深度 | 有因果分析，不甩锅不上价值 |
| 职业叙事 | 转岗动机自洽，与目标岗位（Go 后端/开发）一致 |
| 情绪稳定 | 失败故事讲得坦荡，不防御不慌张 |

## 5. 面试官脚本（给陪练 / AI 面试官的指令）

### 5.1 开场白（背熟，30 秒）

> 「这是模拟面试第 X 场，四轮，每轮 45-60 分钟。我会按真实交易所面试的节奏来：先算法、再系统设计、再项目深挖、最后行为。录音开着了。不认识的词允许问。你可以随时在白板/纸上看不到的地方做笔记。准备好了吗？」

### 5.2 面试官的角色纪律

1. **只暴露问题，不给答案**：被面试者卡住时，用追问引导（「你考虑过边界吗？」「这个组件的容错呢？」），不直接说解法。复盘时再完整讲答案。
2. **控制节奏**：每题超时 25% 直接打断换题——按真实面试风格（题做不完很正常，看的是过程分）。
3. **扮演「不懂的面试官」**：系统设计轮要求被面试者把你当成不懂行的同事，强迫他把每个组件讲人话——这同时训练表达能力。
4. **录音标记**：听到高光时刻（条理清晰的 30 秒）与崩坏时刻（卡壳 2 分钟以上 / 说错术语）在笔记本记时间戳，复盘对着回听。

### 5.3 「面试官会打断的 3 种时刻」练习（每场必做）

打断是真实面试的常态，必须练习被突然打断后 10 秒内恢复：

| 时刻 | 真实面试中长什么样 | 打断练习操作 | 应对要点 |
|---|---|---|---|
| 1. 方向跑偏 5 分钟 | 候选人在一个无关细节（如某 API 参数）上钻牛角尖 | 面试官喊停：「你说的这个和核心问题有关吗？回到主线。」 | 立刻用一句话承认偏差、复述主线任务、继续；训练「被打断不慌、不辩解」 |
| 2. 在背稿而非讲 | 项目自述像朗读简历，没有推理过程 | 面试官打断：「停，这个细节你不要背——为什么当时这么选？告诉我你的思考过程。」 | 从「背稿模式」切到「对话模式」——平时练：每段讲述稿后加 3 个「为什么」问题自问 |
| 3. 忽略需求自说自话 | 设计了一版 A 方案但没确认用户需求（如没问规模） | 面试官打断：「等一下，你还没问我要多少 QPS、要不要钱，你怎么就开始画图了？」 | 固化流程：接到题先张口问 3 个澄清问题再动手；练习「被提醒后补问而不是嘴硬」 |

**练习方法**：每场 Mock 中面试官必须至少打断 1 次（三种轮换着来），并在评分卡“打断恢复”维度打分（1-5：10 秒内回到主线 = 4-5 分）。

### 5.4 收尾（每轮结束）

> 「这轮结束。我记了几个点复盘时给你：一个是……（等全场结束后再详说，避免影响后续轮次）。」

### 6.2 及格线与改进闭环

- **单轮及格线**：平均 ≥ 3.0（低于 = 该模块内容不达标，回到对应材料复习并加练一场专项 Mock）。
- **整场目标**：三轮均 ≥ 3.5 + 行为轮 ≥ 4.0，才算「可投递状态」。Mock1 允许有明显短板——它就是用来暴露的；Mock3 必须达标。
- **改进闭环**：每场结束时面试官给 ≤5 条改进点，被面试者 24 小时内写「改进计划」：每条 = 具体动作 + 时间 + 验证方式（如「算法第 1 题先开口问输入范围——接下来一周每题进场先写下 3 个澄清问题再动笔」）。下次 Mock 开场先复述上轮计划兑现情况。
- **自评分规则**：被面试者先自评再听面试官评分；差异 ≥ 2 分的维度 = 自我认知盲区，必须复盘原因（通常是自己没意识到卡壳有多久 / 把「想对了」当「讲对了」）。

## 7. 与真实面试衔接（投递后）
