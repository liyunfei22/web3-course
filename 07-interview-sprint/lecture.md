## 2. W18 系统设计周：8 题 × 45 分钟白板

### 2.1 面试官视角：系统设计题到底考什么

- 直觉：设计题不是考「背出一张标准图纸」，而是考「面对一个开放问题时，你敢不敢打开一个稳定的思考路径，并在每一步做出有代价意识的选择」。面试官从你的路径里判断：他入职后能不能独立拆需求、敢不敢拍板、出故障时会不会慌张。
- 定义：答题路径 = 需求澄清 → NFR（吞吐/延迟/一致性）→ 架构图 → 核心模块 → 数据模型 → 故障与退化，最后对照自己的项目收尾。跳过任一环节都会当场被测试：跳澄清 → 被问「边界场景呢」；跳故障 → 被问「这台挂了怎么办」。
- 给分点集中在三处：有数字的 NFR、成对出现的取舍（trade-off 永远两个一起讲）、与真实项目的对应物。这三处也正是 W18 每天训练的三个输出。

### 2.2 固定答题流程（六段式，每题必走）

1. 需求澄清（2-3 分钟）：用户是谁、请求是什么、规模多少用户多少 symbol、哪些功能范围外（例：不做合约、不做社交）。
2. NFR 量化（3-4 分钟）：吞吐（订单/s、连接数、消息/s）、延迟（p99 或 p50）、一致性（账户强一致、行情最终一致）、可用性（RTO/RPO）。
3. 架构图（8-10 分钟）：先画 4-6 个组件方框与数据流方向，再补消息中间件与存储。
4. 核心模块（10-12 分钟）：每个模块一句话职责 + 一个关键决策（数据结构/单线程/分片键），不要讲全部细节。
5. 数据模型（5-6 分钟）：表/事件/键/幂等键长什么样，一笔资金或一笔订单的生命周期。
6. 故障与退化（5-6 分钟）：单点列表、级联风险（Kafka 挂了订单停还是熔断降级）、恢复手段。
   收尾（2-3 分钟）：对照自己的项目讲（见 2.5）。

- 训练要点：顺序即给分点。练 4 天后应达到「不用看清单也能整段走完」；走不完的环节是当天回炉重点。

### 2.3 45 分钟白板时间盒

| 环节 | 分钟 | 必须产出 |
|---|---|---|
| 澄清 | 3 | 3 个问题 + 2 个边界外声明 |
| NFR | 4 | 3 个数字（吞吐/延迟/一致性） |
| 架构图 | 10 | ≥4 组件 + 数据流方向 |
| 核心模块 | 12 | 每模块 1 决策 |
| 数据模型 | 6 | 2 张表或 2 个事件 + 幂等键 |
| 故障与退化 | 5 | 2 个单点 + 1 个降级策略 |
| 项目对照 | 3 | 1 段「我做过 X + 数字」 |
| 缓冲 | 2 | — |

- 计时器必须开；白板用纸笔或 Freeform 皆可，重点是边说边画，画是给面试官的眼睛看的，不是给自己看的。

### 2.4 1 页英文答案稿（每题 1 页 A4，七段固定）

1. Requirements & scope：1-2 行需求 + 2 个边界外问题。
2. NFR：throughput / latency / consistency，全部带量级。
3. High-level architecture：组件名 + 连接线，一句话拓扑。
4. Core modules：每模块 1 句职责 + 1 个关键决策。
5. Data model：表/事件/键/幂等键。
6. Trade-offs：2 个取舍 + 各自代价。
7. Failure & degradations：2 条。

- 模板即 ../interview/system-design-8.md 每题的「1 页英文答案稿模板」，只准用自己的语言重写，不许照抄模板句。
- 数字优先：p99 < 50 ms 好过 fast；12 confirmations 好过 "a few blocks"。做不到一寸：把每题要求的具体数字背进英文稿。

### 2.5 与旗舰项目对照的讲法（每题必挂）

- 8 题每一题都有 P2/P1 实锤（映射表见 ../interview/system-design-8.md 开头，每题「与旗舰项目对照的讲法」节），对照三段式：
  ① 我做的 X 对应你问的 Y（挂模块名 + ADR 编号，如 ADR-003 扫块双轨）→ ② 我的实测数字（k6 报告 p99/覆盖率，README 成果清单里有）→ ③ 生产环境我会加 Z（把题目要求的高可用/安全/运维补上，主动亮出差距）。
- 常见错误：只在最后补一句「我项目里做过」——要在第 3、4 段讲架构与模块时就把自己的实现嵌进去，最后收尾讲差距。

### 2.6 W18 常见坑与排查

- 坑 1：跳过澄清直接画图 → 用 2.2 清单对表自查，缺一段重走一次。
- 坑 2：NFR 只写「高吞吐」没有数字 → 每个 NFR 后强制跟一个量级。
- 坑 3：只讲「我们怎么做的」不讲「为什么」→ 每题硬性讲满 2 个取舍。
- 坑 4：45 分钟超时 → 时间盒强制，超时就停笔进入对照环节，超时本身也是数据（写进白板日志）。
- 坑 5：英文稿超 1 页 → 七段各限 1-2 行要点，塞不下说明还没想清楚重点。

交易所场景对应：W18 的 8 题就是交易所后端岗面试的全部真实业务面（撮合/充提/行情/账务/对账/钱包/性能/可用性）；训练目标是把你写过的 P2/P1 代码「翻译」成系统语言并补上生产差距。

## 3. W19 算法冲刺周：题单 180 题 + Go 并发专项 15 题

### 3.1 180 题分类题单是什么、怎么用

- 题单 = 分类清单（数组/哈希/双指针/滑动窗口/链表/栈/队列/堆/二分/树/图/DFS/BFS/回溯/DP/贪心），Medium 为主。
- 它汇总全期积累：前面每阶段每日算法块（45 分钟 × 近 18 周）已划过 100+ 题，W19 的任务是「补缺 + 分类重刷 + 结算标记」，不是 5 天从零刷 180 道。
- 载体：../interview/algorithms/ 下的题单表格，字段：编号/分类/难度/状态（未刷/已刷/标记）/首刷耗时/二刷日期/备注。题单必须在 D9 前把「未刷」清零。

### 3.2 第一遍规则：30 分钟想不出即看题解 + 二刷标记

- 每道新题限 30 分钟：9:00 开题 → 9:30 无思路直接看题解 → 当天按题解思路独立重写一次 → 状态标「标记」。
- 标记的语义 = 「我欠这道题一次独立重做」，不是挫败记录；标记数量不焦虑，最后 5 天就是为标记准备的。
- 同分类连刷是模式识别的关键：8-12 题/天是快刷的正常节奏（含看题解与二刷时间）。
- 一律用 Go 写；每题保留运行痕迹（提交记录截图或用例输出），这是「刷过」的外部证据。

### 3.3 周末错题重刷（D10 执行，其余周末顺延同一流程）

- 重刷只看「标记」题：先凭记忆写 → 卡住再看题解 → 还卡再标一次（标记会滚动，重刷一次通过后取消标记）。
- 重刷格式：先口述思路（30 秒），再手写核心函数签名与边界用例，不抄完整代码。

### 3.4 最后 5 天（W20 每日算法块）只刷标记题

- W20 的 45 分钟算法块不做新题：滚动队列重刷标记题，每天 6-8 题，以「独立一次通过」为过关标准。
- 原则：第一遍求覆盖（W19 前半），结算期求准确（W20），两道坎各自独立计时。

### 3.5 Go 并发专项 15 题必做（W19 硬性要求）

- 必做原因：交易所 Go 岗几乎必面并发（撮合流水线/推送扇出/消费组全是并发心智），这 15 题是 roadmap 定死的必做项，不随弹性档位削减。
- 15 题固定清单：交替打印 1-100 奇偶数、交替打印 ABC、worker pool 限并发、生产者-消费者（多生产者多消费者 + 幂等）、超时控制（context）、令牌桶限流器、fan-in/fan-out、带优先级队列的订单处理（撤单优先）、并发安全 LRU、信号量限流、pipeline 关闭顺序、errgroup 聚合错误、singleflight 防缓存击穿、优雅停止 worker（close + done 双保险）、channel 双关闭陷阱排查。
- 每题 30 分钟限时；跑通后给关键行写一句「为什么这样写」注释——自查你写注释时的逻辑，不是代码风格。
- 每题做完对照 ../interview/go-deep-60.md 对应条目的「面试官追问」自测一次，自测结论记入 60 题自测记录。

交易所场景对应：限流器 = Phase 2 网关令牌桶；worker pool = 消费组线程模型；优先级队列 = 撤单先于新单（资金尽早释放）；幂等消费 = Phase 3 充值入账幂等键。15 题每题都要能答出「交易所哪里用得上」，这是 Go 并发题拿高分的通用招数。

## 4. W20 英文 + 简历 + Mock

### 4.1 100 词中英术语库

- 100 词 = CLAUDE.md 术语表全部词汇 + 各阶段讲义高频词（撮合/订单簿/三栏/幂等/Outbox/确认数/重组/冲正/归集/对账/资产储备证明/事件溯源/预写日志/快照/价格-时间优先）+ 通用面试词（whiteboard、trade-off、p99、confirmation、throughput……）。
- 使用法：双语卡片（中 → 英口述 + 一句例句）；每词至少 3 轮：D11 成稿背诵 → D12 听写一轮 → D15 终轮听写；错词单独回炉，听写错误 ≤10 词为达标线。
- 载体：../interview/english/terms-100.md + 个人听写记录文件。

### 4.2 1 分钟自我介绍磨稿流程

- 结构：名字与当前状态（1 句）→ 转岗动机一句话（为什么 Go 后端、为什么交易所）→ 三个卖点（各 1 句带数字）→ 收尾目标（1 句）。
- 磨稿流程：中文先写（内容定型）→ 译英文 → 录音 → 对照结构改 → 再录，共三版（初稿/二稿/终稿），时长各 55-75 秒，终稿英文。
- 从 D12 起，每日英语/八股块轮播终稿录音一遍；录音文件是「磨过」的证据，也是回听的素材。

### 4.3 30 分钟项目讲述稿（旗舰/P1/DEX 三版，录音回听）

- 旗舰版 30 分钟（D12 完成）：P2 五周故事按模块讲（撮合 → 账务 → 行情 → 钱包 → 压测），每模块 3-4 分钟：问题 → 方案 → 取舍 → 数字 → 踩坑。
- P1 版与 DEX 版各 10 分钟（D13 完成）：同一结构压缩。
- 磨稿流程：成文 → 录音 → 回听记卡壳点与数字不清点（每版 ≥5 条笔记）→ 改稿 → 再录。录音必须完整一段（旗舰 25-35 分钟），不允许分段拼接。
- 每个结论后准备「如果再问一层」的答案，素材来自项目复盘（10 条验收⑨的坑故事库：现象/根因/解法/耗时）。

### 4.4 简历两页法

- 上限两页：第 1 页 = 教育/经历/技能；第 2 页 = 项目 + 技术栈补充；第二页放一半是常态，两页整即「页数合格」。
- 数字驱动：每个项目段 ≥2 个数字（覆盖率/QPS/p99/题量/确认数），全文数字型证据 ≥10 个。
- 项目排序：P2 旗舰占最大篇幅（系统设计 8 题全挂它），P1 其次，P0/P3/P4 各 2-3 行。
- 每版投递微调：JD 关键词进简历原文（技能段按岗位重排），投递表记录中核对「这份简历是为哪个 JD 调的」。

### 4.5 GitHub 组织包装

- 组织主页总 README：一句话定位 + 项目导航表（P0-P4 各：仓库链接 + 3 行简介 + 演示录屏 + CI 绿标）。
- 3 支核心录屏（P2 闭环 6 分钟、P1 充值入账、P3 swap）链接进总 README，验收当天逐一可打开。
- 五个仓库 README 按 10 条验收④互链（总 README ↔ 各项目 README），仓库描述统一英文并带关键词（exchange、matching engine、ledger、kafka、golang）。

### 4.6 投递策略

- 渠道：交易所官网招聘页、内推（Superteam 等社区的交易所频道可用作线索源）、招聘平台筛选（过滤关键词：Go + gRPC + Kafka + Redis，优先「撮合/钱包/链上」相关 JD）。
- 投递表 ≥20 条：公司/岗位/渠道/投递日期/状态，状态列不允许空值；岗位广度大于只投 Top3。
- 时间安排：简历定稿（D15）后集中投出第一批，之后每 2-3 天投一批；投完当天把 JD 存一份到投递表备注（面试前 30 分钟读它）。

### 4.7 2-3 场完整 Mock（四轮评分卡）

- 一场 Mock 四轮：① 算法 45 分钟（30 分钟规则同实战）→ ② 系统设计 45 分钟（六段式）→ ③ 八股 30 分钟（Go 深挖 + 区块链基础）→ ④ 项目深挖 30 分钟（讲述稿任意抽取追问）。
- 评分卡：每轮 0-100，加权总分 ≥70 为该场过关（权重参考 roadmap 第 8 节）；评分卡文件 3 份，4 轮评分每轮都要有数字。
- 流程：D14 两场（第一场找问题 → 30 分钟复盘 → 改 → 第二场验证），D15 一场仿真（英语开场、开摄像头、模拟远程面）；
- 每场后 30 分钟复盘必须产出：扣分点 → 补课清单 → 下场目标，三行写入 ../interview/resume/mock-scores/。

## 5. 冲刺期通用守则（每天对照）

1. 每日算法块一天不停，W20 换为标记题重刷。
2. 每块主任务强制计时：白板 45 分钟、错题 30 分钟、录音回听 ≥2 轮。
3. 所有产出当天 commit，复盘三行入日志。
4. 一天最多抄一次题解——第二天的算法块必须独立重做那道题。
5. W20 每天英语块升级为核心块：自我介绍与讲述稿轮播。
6. 卡壳 30 分钟规则的冲刺版：跳过 → 记录 → 次日回炉，绝不恋战。
7. 睡眠优先：面试状态 = 睡眠 + 白板肌肉记忆，冲刺期不是熬夜期。
